# Tokens to SCSS — Penpot plugin

Собирает по одному SCSS-файлу на **каждый** набор токенов, какой есть в файле (все Sets —
Global/*, Theme/* и любые другие), сохраняя ссылки между токенами как SCSS-переменные
(`$spacing-12: $base-module * 3`, а не `12px`). Составные типы (typography, shadow) —
через SCSS map + `@mixin`. После генерации — кнопки «Скачать» на каждый файл и «Скачать всё
одним .zip».

## Опция «Объединить Global в `_variables.scss`»

Чекбокс под кнопкой «Собрать SCSS-файлы»:

- **Выключен (по умолчанию)** — поведение как раньше: один файл на каждый набор,
  включая отдельные `_global-dimensions.scss`, `_global-typography.scss`, `_global-colors.scss`.
- **Включён** — все наборы, чьё имя начинается с `Global` (`Global/Dimensions`,
  `Global/Colors`, `Global/Typography`, `Global/что-угодно-ещё`), объединяются в один
  `_variables.scss`, в исходном порядке наборов. Остальные наборы (`Theme/*` и любые
  другие) генерируются как обычно, но их `@use` теперь указывает на `"variables"`
  вместо отдельных global-наборов. Если один и тот же токен встречается в нескольких
  Global-наборах — используется первое вхождение, о конфликте пишется предупреждение
  в консоль (`console.warn`), сборка не прерывается.

## Новые возможности (v3)

Под кнопкой «Собрать SCSS-файлы» теперь:

- **Префикс переменных** — текстовое поле. Если указать, например, `s3m`, все генерируемые
  имена переменных получают префикс (`$s3m-spacing-12` вместо `$spacing-12`), но **имена файлов
  и пути `@use` не меняются** — только идентификаторы внутри.
- **Формат вывода** — выпадающий список: «SCSS-переменные» (как раньше) или «CSS custom
  properties». В CSS-режиме файлы получают расширение `.css`, оборачиваются в подходящий
  селектор (`:root` для Global/объединённых наборов, `:root, [data-theme="light"]` /
  `[data-theme="dark"]` — угадывается по имени набора), арифметика вида `{base-module} * 3`
  становится `calc(var(--base-module) * 3)`, а составные typography-токены разворачиваются
  в набор отдельных custom properties (`--name-font-size`, `--name-font-weight`, …) — в CSS нет
  миксинов, поэтому map+`@mixin` из SCSS-режима здесь неприменимы.
- **Наборы токенов (выборочный экспорт)** — после первой загрузки токенов появляется
  сворачиваемый список чекбоксов, один на каждый Set. Если снять галочку с набора, на который
  всё ещё ссылаются другие токены — ссылка не ломается: вместо неё подставляется resolved-значение,
  а в панель предупреждений добавляется соответствующая запись.
- **Цветовые токены (свотч-сетка)** — сворачиваемая галерея всех токенов типа `color` по всем
  наборам, с разрешением ссылок до литерального цвета (даже через несколько уровней `{alias}`).
- **Панель предупреждений** — коллизии имён, подстановки из-за исключённых наборов и т.п.
  теперь видны прямо в интерфейсе, а не только в консоли.
- **Превью и копирование** — у каждого файла в списке результатов кнопки «Просмотр» (разворачивает
  содержимое прямо в панели) и «Копировать» (в буфер обмена, с fallback через `execCommand`,
  если `navigator.clipboard` недоступен в песочнице iframe).
- **Память настроек** — префикс, формат вывода, чекбокс объединения Global и выбор наборов
  сохраняются в `localStorage` и восстанавливаются при следующем открытии плагина.

Изменение любой настройки после того, как токены один раз загружены, **пересобирает файлы сразу**,
без повторного запроса к `plugin.js` — данные токенов кэшируются в памяти интерфейса.

## Что изменилось в этой версии

### 1. Починена иконка
В `manifest.json` путь к иконке был **абсолютным** (`"icon": "/icon.png"`), из-за чего он
резолвился в корень домена, а не в папку плагина — плюс файла `icon.png` не было в репозитории
вовсе. Теперь: путь относительный (`"icon": "icon.png"`, как требует `"version": 2` —
[см. документацию](https://help.penpot.app/plugins/create-a-plugin/#2.6.-step-6.-configure-the-manifest-file)),
и сам `icon.png` включён в архив.

### 2. Индикаторы загрузки
Раньше при клике «Собрать SCSS-файлы» не было видимой обратной связи, если что-то шло не так —
выглядело как «ничего не происходит». Теперь:
- спиннер и полупрозрачная кнопка во время ожидания ответа от `plugin.js`;
- skeleton-плейсхолдеры на месте будущего списка файлов;
- запрос повторяется автоматически до 2 раз (по 3 сек), если ответ не пришёл;
- если после всех попыток ответа всё ещё нет — понятная ошибка с перечнем вероятных причин
  (не тот протокол загрузки, не выдано разрешение `library:read`, в файле нет токенов) вместо
  тишины;
- вся коммуникация логируется в консоль (`[Tokens to SCSS] …`) для отладки.

### 3. Стили в духе Penpot UI Kit
`@import "@penpot/plugin-styles/styles.css";` — рекомендованный Penpot способ, но он работает
через сборщик (`npm install @penpot/plugin-styles` → импорт в CSS, обрабатывается Vite/webpack —
[см. официальный гайд](https://help.penpot.app/plugins/create-a-plugin/#plugin-styles)). У этого
плагина нет сборки (чистые html/js/css, без npm), так что сам пакет физически не установить в
таком виде. Вместо этого `styles.css` вручную воспроизводит визуальный язык Penpot, опираясь на
то, что удалось подтвердить из открытых источников:
- тёмная тема по умолчанию с mint-акцентом (`--color-accent-primary`, в реальном Penpot это
  `$mint-150` — см. [UI Guide](https://help.penpot.app/technical-guide/developer/ui/));
- атрибут `data-appearance="primary"` на кнопках — это буквально соглашение из официального
  [penpot-plugin-starter-template](https://github.com/penpot/penpot-plugin-starter-template)
  (`<button data-appearance="primary">`), не моя выдумка;
- скруглённые контролы, компактная типографика.

Если у вас будет сборка через Vite — замените `<link rel="stylesheet" href="styles.css">` в
`index.html` на настоящий `@import "@penpot/plugin-styles/styles.css";` в вашем глобальном CSS
и уберите `styles.css` из этого репозитория.

### 4. Тестирование (что реально проверено)
Раньше генерация была протестирована только на реальных данных, но НЕ на реальном
click → postMessage → response → render потоке — отсюда, вероятно, и родилась ошибка
«ничего не происходит», которую не поймать чтением кода. В `test/` теперь два дополнительных
прогона:
- `simulate_flow.js` — полная симуляция DOM (без браузера) и happy path: клик по кнопке →
  `postMessage` в `plugin.js` → ответ с реальными токенами → рендер списка файлов → скачивание
  файла и .zip. Проверяет, что на каждом шаге состояние (текст статуса, классы, disabled) верное.
- `simulate_timeout.js` — воспроизводит именно repoted-баг (`plugin.js` не отвечает) и проверяет,
  что вместо тишины пользователь видит понятную ошибку через ~9 секунд, а кнопка снова активна.

```bash
cd test
node run.js                    # генерация на реальном дампе токенов + проверка баланса скобок
node run_merge.js              # опция "Объединить Global в _variables.scss" (оба режима)
node run_v3.js                 # логика префикса / CSS-режима / выборочного экспорта (18 проверок)
node simulate_flow_v3.js       # полный DOM-флоу: чекбоксы наборов, свотчи, превью, копирование,
                                # префикс, переключение формата, localStorage — через самодельный DOM-шим
node simulate_timeout.js       # путь без ответа от plugin.js
```

## Файлы плагина

```
manifest.json   — метаданные и permissions
plugin.js       — sandbox-скрипт (доступ к penpot.library.local.tokens)
index.html      — интерфейс плагина
styles.css      — оформление в духе Penpot UI Kit
ui.js           — вся генерация SCSS + ZIP-writer + скачивание + индикаторы загрузки
icon.png        — иконка 56×56
```

## Важно: плагину нужен публичный URL

Penpot загружает плагин по `manifest.json` URL, который должен быть доступен из браузера,
где открыт Penpot — **просто открыть файлы с диска (`file://`) не получится**, и именно это
чаще всего выглядит как «кнопка ничего не делает» (потому что `plugin.js` в таком случае вообще
не запускается как настоящий Penpot-плагин). Варианты:

### Быстрее всего — статический хостинг с перетаскиванием
1. Зайдите на [Netlify Drop](https://app.netlify.com/drop) (не требует аккаунта для разового
   деплоя) или аналог (Vercel, Cloudflare Pages, Surge.sh).
2. Перетащите папку со всеми файлами плагина в окно загрузки.
3. Скопируйте выданный URL и допишите `/manifest.json` — это и есть URL плагина.

### Локально для разработки
```bash
npx serve .
# или: python3 -m http.server 4400
```
Плагин будет доступен на `http://localhost:4400/manifest.json`.

### GitHub Pages
Положите содержимое в репозиторий, включите Pages для ветки — получите
`https://<user>.github.io/<repo>/manifest.json`.

## Установка в Penpot

1. Откройте файл в Penpot.
2. `Ctrl+Alt+P` → «Plugin manager».
3. Вставьте URL вида `https://.../manifest.json` → «Install».
4. Откройте плагин из списка.
5. Нажмите «Собрать SCSS-файлы» → скачайте нужные файлы или всё разом через .zip.

## Если снова «ничего не происходит»

1. Откройте консоль разработчика (F12) в Penpot — все шаги логируются с префиксом
   `[Tokens to SCSS]`. Если после клика в консоли вообще нет строки
   `requesting tokens from plugin.js` — значит `ui.js` не подключился (проверьте, что открываете
   плагин по `https://`/`http://`, а не как локальный файл, и что `index.html` реально отдаёт
   `<script type="module" src="ui.js">`).
2. Если строка есть, а `plugin.js received message` не появляется — проверьте разрешение
   `library:read` в установленном плагине (Plugin manager → настройки плагина).
3. Через ~9 секунд плагин сам покажет ошибку с этими же подсказками в интерфейсе — не нужно
   гадать вслепую.

## Как это устроено внутри

- `plugin.js` работает в изолированном sandbox-контексте, где доступен объект `penpot`,
  но нет DOM/Blob API — поэтому он только читает `penpot.library.local.tokens.sets`
  и пересылает данные в iframe через `penpot.ui.sendMessage`.
- `ui.js` работает в iframe (обычный DOM), получает данные через `window.addEventListener("message")`,
  генерирует SCSS и создаёт файлы на скачивание через `Blob` + `<a download>`
  (это и требует permission `"allow:downloads"` в manifest.json).
- Наследование токенов сохраняется: если значение токена — это `"{other.token}"`,
  в SCSS это становится `$other-token`, а не подставленное число/цвет. Если токен
  ссылается на токен из ДРУГОГО набора, файл получает `@use "<тот-набор>" as *;`.
- Токены внутри набора топологически сортируются, чтобы зависимые переменные не
  оказались объявлены раньше того, на что они ссылаются.
- Для цветов используется исходное `value`, а не `resolvedValue` — у Penpot `resolvedValue`
  теряет альфа-канал для `rgba()`-литералов.
